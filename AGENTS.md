# Project instructions

Read [HACKATHON_RULES.md](HACKATHON_RULES.md) before planning or changing this project.

- Treat the user-supplied Graph Hacks rules as acceptance constraints.
- Intended track: Agent Memory and Coordination. Do not claim a submission has been made.
- FalkorDB must power essential product behavior, not just a visualization or optional sidecar. Do not describe the current SQLite prototype as meeting that requirement.
- Do not silently fall back to SQLite for the essential graph workflow while claiming FalkorDB compliance.
- Use only permitted public, synthetic, or participant-owned data; do not import restricted or personal data.
- Preserve existing user data. A database migration requires its own scoped implementation and verification.
- Keep implemented features distinct from plans and simulations. Document graph schema, required Cypher/algorithms, setup, and AI assistance accurately.
- Help the participant understand and verify the code. Do not invent participant contributions, verification, team details, coding dates, or submission completion.
- Saving these rules does not by itself authorize a database migration, deployment, public repository creation, or submission.
