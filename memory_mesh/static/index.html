01 / THE PROBLEM

Why investigate the same pattern twice?

Security investigations produce useful knowledge: which accounts were involved, which pattern appeared, and which response an analyst approved. If each agent starts with an empty context, that work has to be repeated.

Mesh keeps that knowledge in a shared store. A new investigation can recall past cases, add its own findings, and leave an auditable trail for the next analyst.

03 / WHAT IS RUNNING

Persistent data. Deterministic workers.

  • Python handles the API and three sequential workers.
  • FalkorDB stores incidents, memories, handoffs, and audit events.
  • Keyword overlap retrieves memory; no LLM or vector search is connected.
  • Tenant filters scope data. The tenant switcher is simulated identity, not authentication.
04 / READING THE DEMO HONESTLY

The 90s → 30s number is modeled.

The current code assigns 90 seconds to the first workflow and 30 when a prior workflow exists for that tenant and user. It does not measure investigation speed or verify similarity for that timing rule.

Confidence and “useful memory” values are heuristics. The pipeline shows saved outcomes after the request completes; it is not a live worker stream.
